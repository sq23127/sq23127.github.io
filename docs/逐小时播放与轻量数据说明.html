逐小时播放与轻量数据说明

当前版本 2.2；更新日期：2026-10-26。

波浪恢复为每小时一帧，没有删掉任何小时。当前温度、盐度、海流的来源仍是 ORAS5 月平均，不伪造逐小时变化。数据网格默认 0.5°，保留处理结果的四位小数。

现在直接怎么用

  • PyCharm 中：停止旧运行进程，重新运行 启动可视化平台.py，浏览器加载的是构建后的 Vue 界面。
  • 只看图和播放：将 single-html-release/海洋可视化平台_双击即用.html 发给对方，用新版 Chrome / Edge 打开。底图与 Cesium 辅助资源需联网，不用安装 Python 或 Node。
  • 要下载与处理：使用新版本 Windows 完整运行包，完整解压后双击 OceanPlatform.exe，保持程序窗口运行。对方在数据工作台配置自己的 CDS 令牌，并自行在 CDS 接受对应数据集许可。
  • 已有处理数据：左侧导入优先选择 .ocean；JSON 兼容保留。原始 NetCDF 在数据工作台导入处理，不能直接当作页面数据。

数据为什么变小、解析为什么变快

旧方法把每一小时的每个网格点都写成 JSON 数字和数组，再解析、复制整个数据对象。新版使用带帧索引的压缩二进制，后台线程解压后传递 ArrayBuffer；只有使用某帧时才展开它的网格，展开后的网格缓存最多 24 张，色标范围直接使用索引中的统计值。

这里是按需展开网格，不是通过网络逐小时下载。首次仍需读取并解压整份轻量文件，编码数据常驻内存。超长时段仍建议分月处理、缩小海域，不能认为任意多年数据都没有内存开销。

以后解析新数据怎么做

直接在 PyCharm 运行 build_json.py，现在默认逐小时、0.5°、流式生成轻量文件。需要指定时段时，在终端运行：

python build_json.py --start 2026-06-01 --end 2026-07-31

# 等价的显式写法
python build_json.py --frequency hour --step 0.5 --compact-only

# 确实需要完整 JSON 兼容导出时才运行（文件会大得多）
python build_json.py --frequency hour --step 0.5 --json-compat

主输出为 02_Geojson/scs_field.ocean，发布副本为 public/data/scs_field.ocean。页面优先读取轻量文件；旧 JSON 不会自动删除，但它不再是当前页面的主数据。此前两帧月平均结果另存于 backups/before-hourly-20261026/scs_field_monthly.json。

不要用 --frequency month 压缩体积，这会丢掉小时变化。--step 0.2 仍可显式选择，但点数约为 0.5° 的六倍，文件、处理和绘制成本都会增加，并不会提高 ERA5 波浪原始空间精度。

修改代码后怎么打包

# 在开发电脑、项目目录中执行
node scripts/prepare-assets.mjs
pnpm run build
node scripts/build_single_html.mjs
node scripts/check_single_html.mjs

# Windows 完整程序，需项目打包依赖
python scripts/build_portable.py --skip-ui-build --zip

普通 Vue 构建在存在 .ocean 时不再携带旧的巨型数据 JSON；单文件 HTML 直接内嵌压缩后的轻量数据，不再重新解析整份 JSON。Windows 包仍需包含 Python 科学计算运行库，程序包总大小不能与单独数据文件大小混为一谈。
