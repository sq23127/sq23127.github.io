Vue 平台开发维护与独立网页交付说明

面向开发者：平时改什么、到哪里改、如何验证，以及怎样把最新版交给其他人独立使用。

适用版本：当前本机 Vue 3.5.44 + Vite 8.3.5 + Cesium 1.118.0 工程，核对日期 2026-10-23。“最新版”指本项目当前 Vue 版，不表示将所有依赖升级到最新发布版。

新增完整版：接收者需在自己电脑下载、导入处理并可视化时，使用 Windows 完整运行包 OceanPlatform.exe，见 完整版平台使用说明。下文关于 dist、start_platform.py 的静态交付属于仅查看模式；开发入口 platform_server.py 提供本机完整服务。

1. 先确认你正在修改哪个版本

当前 Vue 工程在 D:\Python项目组\Ocean_project。工作说明中的路径均相对此工程根目录。打开 PyCharm 后先核对项目路径，避免误改旧版克隆目录。

GitHub 的 codex/legacy-no-vue 是刚上传的旧版存档，不是本说明对应的 Vue 源码。当前 Vue 工程在本机。把旧版分支拉下来，不会得到 src/App.vue 等 Vue 文件。
入口用途会读取哪里
pnpm run dev → 5173日常改代码、调样式；支持热更新src、public；开发入口为根 index.html
pnpm run preview → 4173检查已经构建的成果dist；不替你重新构建
start_platform.py → 8000在 PyCharm 运行，打开已有成果dist；不下载、不转换、不编译

最容易误会的一点：你修改了 src 或 public，但浏览器开着 8000，画面仍旧，这是因为 8000 读取上一次 dist。需要先构建，或改用 5173 调试。根 index.html 仅是 Vue 入口，不能再作为旧版单文件页面双击交付。

2. 你每天维护工程的固定流程

第一次准备开发环境

推荐 64 位 Node.js 22.12 或更新的兼容 LTS。工程要求 ^20.19.0 || >=22.12.0，但 pnpm 11 自身需要 Node 22 或以上。在工程根目录终端执行：

npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm run dev

浏览器打开 http://127.0.0.1:5173/。已有依赖时，日常直接运行 pnpm run dev。开发与预览端口启用严格检查，被占用时会停止，不会自动换端口。

首次运行需参考 .env.example 新建 .env.local，填地图客户端令牌。当前本机已保留原来的地图配置；迁移到其他机器时要单独准备。

每次修改

  1. 先备份或提交本次修改前的源码。
  2. 运行开发服务，在 5173 修改并查看；大数据变化后手动刷新。
  3. 按下方速查表修改对应源文件，避免直接改 dist。
  4. 涉及播放、导入、生命周期或数据逻辑时运行测试；仅改文字或轻微样式时，浏览器核对即可。
  5. 运行构建与预览，确认打包后也正确，再交付完整 dist。
pnpm test
pnpm run build
pnpm run preview

以上命令要在工程根目录执行。若只使用 npm，可用 npm install、npm run dev、npm test、npm run build；npm 不读取 pnpm-lock.yaml，因此团队严格复现优先统一 pnpm 和锁文件。

4. 常见界面修改：可以照着做

A. 改平台名称和地图账户

修改根目录 .env.local：

VITE_APP_TITLE=某某单位海洋环境可视化平台
VITE_CESIUM_ION_TOKEN=该应用使用的Cesium客户端令牌

停止并重新运行开发服务；正式版重新构建。VITE_ 变量会进入浏览器程序，这里只放地图客户端令牌，不放 CDS 私密下载令牌。换维护单位时，在 Cesium 账户为该应用配置专用、最小权限令牌及允许的真实访问地址；查看者无需每个人注册 Cesium。

B. 改按钮文字

在 ImportPanel.vue 的 modes 中，把 ['swh', '波高'] 改为 ['swh', '有效波高']。保留 swh；它用于查找数据和分发动作。imports 中的 field/current/temp/sal/wave 同理。

C. 移动信息框

platform.css 搜索 #dataAside，把 right:16px 改为 right:24px 可把整组右栏向左移。它里面依次是点位数据、数据信息、图例；需要互换顺序时改 DataDetails.vue 的 section 顺序。不要分别给三个子框设置互相冲突的绝对定位。

搜索 #infoBox #dataSource 可改数据来源字号；#infoBox .r 的网格列宽负责标签与数值对齐。改完同时检查来源长文字、窄屏和播放栏是否遮挡。

D. 改初始镜头

src/config.js 中改为：

initialBounds: { west: 118, south: 24, east: 128, north: 34 },

这只改变初始镜头。要显示东海对应的新数据，下载和转换范围也需一起改，见第 6 节。继续保留 import.meta.env.BASE_URL 拼接数据地址，便于网站部署在子目录。

5. 播放、颜色、画质和粒子怎么改？

A. 改默认播放速度

引擎搜索 function frameDelay()，当前为 1100/(Number(speedSelect.value)||1)。例如把 1100 改为 1500，1× 的目标间隔变为 1.5 秒。实际切帧还受贴图生成、设备和网络影响，不能保证所有电脑都达到这个速度。

需要默认选 2×：platformState.js 中把 state.tbSpeed.value = state.tbDirection.value = '1' 拆开：

state.tbSpeed.value = '2'
state.tbDirection.value = '1'

想加 8×，在 TimeControls.vue 的 tbSpeed 选项中增加 <option value="8">8×</option>。同步改 TimeControls.vue 与引擎中描述“1× 约 1.1 秒”的提示；改速度不会提高源数据时间分辨率。

B. 改切帧过渡

引擎搜索 showSurface、fadeSurfaceLayers、transitionMs、flushScrub。自动播放的渐变按帧间隔计算并限制到 120–600 ms；拖动预览为 120 ms，释放定位为 180 ms。调长更柔和，但会更慢；要改上限也需检查 showSurface 内的 600 ms 限制。

保留“新图解码与预热后再淡入”“旧图保留”“取消过期请求”“最后一次拖动优先”这几段逻辑。不能为了简化代码每次先清空全部图层，否则会重新出现闪屏。

C. 改色带

引擎搜索 const STOPS。数值是 0–1 RGB，当前蓝→青→绿→黄→红。可改成下面的五段配色：

const STOPS = [[0.08,0.12,0.45],[0,0.55,0.8],[0.2,0.8,0.7],[1,0.85,0.25],[0.8,0.1,0.1]];

同时修改 platform.css 的 #legend .bar 渐变，使图例与贴图一致。目前 colorAt 中有末段索引 4，常规改色保持五个控制点；若增减段数，要一并修改索引。色标范围由 updateRangeScale 按所选区间固定，不要恢复成逐帧自动变化后又拿颜色直接比较。

D. 调清晰度与性能

引擎 surfaceTextureSize：流畅 1536，自动 2048–2560，高清 3072；applyDisplayQuality 控制像素比上限和地球细节。纹理边长翻倍时，像素量约变成四倍。先用原始长时段数据实测，再增加尺寸。

改默认不透明度时，核对引擎中 surfaceOpacity 的初始化及回退值，并同步 platformState.js 中 surfaceOpacity.value、opacityValue.text。当前默认 0.92 / 92 / 92%。只改状态会出现界面数值与首次绘图不一致。

E. 调粒子数量和速度

引擎搜索 P_N=900,TRAIL=6，实际线段数量为 P_N × (TRAIL−1)，当前 4,500 条。低配设备可先试 P_N=500，保留 TRAIL≥3。DT=8*3600 是轨迹演示推进尺度，buildWaveUV(0.6) 是波浪粒子显示速度；这些不是实测传播速度，不能据此解释真实到达时间。

修改以上逻辑后运行 engine / lifecycle 测试，再实际检查海流、波浪两类粒子及切换、销毁行为。不要用 Vue 深度响应式或 deep watch 包装 Viewer、全部网格、粒子和贴图缓存。

6. 更新时段、区域与数据：正确的完整流程

目录关系是：

download_data.py → 01_data/原始NetCDF
build_json.py → 02_Geojson/scs_field.json
             → 校验并发布 public/data/scs_field.json
Vue 开发版读取 public/data
pnpm run build → dist/data + dist/assets + dist/cesium 等

下面 Python 命令都在根目录运行，使用本项目虚拟环境。新电脑先安装 Python、建立 .venv，再安装 numpy、pandas、xarray、scipy、h5netcdf、h5py、cdsapi、requests。下载前运行 download_data.py --setup 配置自己的 CDS，并在数据集页面接受条款。详细账户步骤见《数据与交付说明》。

A. 只更新现有 JSON

将符合平台格式的新数据放到 02_Geojson/scs_field.json 后：

.\.venv\Scripts\python.exe check_json.py 02_Geojson/scs_field.json
.\.venv\Scripts\python.exe pack_json.py

pack 默认校验并发布至 public/data/scs_field.json，不修改 Vue index.html。刷新开发页面可读取；8000 或线上正式版必须重新构建并更新部署。

B. 下载两天波浪，做隔离试验

.\.venv\Scripts\python.exe download_data.py --start 2026-06-01 --end 2026-06-02 --fields wave --output-dir 01_data/trial_wave --plan
.\.venv\Scripts\python.exe download_data.py --start 2026-06-01 --end 2026-06-02 --fields wave --output-dir 01_data/trial_wave
.\.venv\Scripts\python.exe build_json.py --input-dir 01_data/trial_wave --output 02_Geojson/trial_wave.json --publish-to public/data/trial_wave.json --start 2026-06-01 --end 2026-06-02 --frequency hour --step 0.5 --fields swh mwd mwp

第一条只在本地打印请求，不联网、不验证服务当前可用性。第二条实际下载。第三条生成独立试验 JSON，不覆盖当前默认数据。要查看试验，可用页面“导入 多合一”选择 trial_wave.json；刷新后仍回到默认数据。想把试验设为默认，改 config.js 的 dataUrl 为 `${import.meta.env.BASE_URL}data/trial_wave.json`。

C. 重新处理原有完整资料

.\.venv\Scripts\python.exe build_json.py --input-dir 01_data --start 2026-06-01 --end 2026-07-31 --frequency hour --step 0.5

此命令会更新默认处理结果和默认发布数据。递归输入目录不能混放同字段、同时次的冲突版本；不要仅把旧文件移进输入目录的子文件夹。--json-only 可只生成处理结果；--html 已停用，Vue 版使用 --publish-to。

D. 换海域时要联动三处

位置东海示例顺序
下载--area 34 118 24 128北、西、南、东；仅 ERA5 区域下载有效
转换--bounds 118 128 24 34西、东、南、北；ORAS5 全球资料在此裁剪
config.jsinitialBounds: {west:118,south:24,east:128,north:34}只控制镜头

海岸遮罩约覆盖 98–146°E、6°S–50°N，扩大到此范围外需更新 public/data/land-polygons.json。遮罩是经纬度多边形环数组，不是随便放一个标准 GeoJSON 就能读取。

当前波浪是 1,464 个小时帧，温盐流各只有两个月平均帧；全部按 UTC。0.5° 是角度网格，纬向约 56 km。改 hour、改更密 step、提高清晰度或平滑动画，都不会产生原始数据不存在的真实细节。

7. 要增加“波周期”等新显示要素时

波周期 mwp 已在数据中，但当前没有独立显示按钮。增加它不能只添加一个按钮，需要把整条链路接通：

  1. 确认 JSON 的字段、单位、每帧时间与网格；先运行 check_json.py。mwp 单位为秒。
  2. 引擎的 MODE_FIELDS 增加一个模式，例如 mwp:["mwp"]；SURFACE_MODES 增加 mwp:["mwp","平均波周期","s"]。
  3. 检查 loadDataset 中候选 modes 数组，按需要加入 mwp；clearAll 中补 removeSurface("mwp")，防止旧图层留存。
  4. platformState.js 的 state.modes 增加 mwp；ImportPanel.vue 的 modes 增加 ['mwp','波周期']。
  5. 需要鼠标点位显示时，在状态 ids 中增加例如 htMwp，在 DataDetails.vue 的 pointFields 增加对应行，并在引擎鼠标事件里通过 sampLL 采样后写入该状态。
  6. 搜索引擎所有硬编码模式列表，逐一确认新模式；补新增模式、清除、切帧与导入的测试。

这是修改路线，当前交付代码没有自动增加波周期按钮。若是完全新的变量，还需扩展 build_json.py 的 ALIASES / 单位等、check_json.py 的字段定义、前端 FIELDS / IMPORT_FIELDS 与相应元数据识别；下载源也可能需要新接口适配。

8. 给其他人独立使用网页：具体交什么？

当前 Vue 版可以作为独立静态网站运行，不需要你的开发服务器或 Python 数据处理后台。但交付单位是完整 dist 文件夹，不是单独一个 HTML。浏览器需要 HTTP(S)，底图仍需网络。

A. 你先准备最终成果

  1. 确认 public/data 是最终数据，.env.local 是本次部署使用的地图客户端配置。
  2. 运行 pnpm run build。prebuild 会准备 Cesium 本地资源和说明，再生成 dist。
  3. 运行 pnpm run preview，在 4173 检查实际构建。修改源码后需要再次 build；preview 不会自动构建。
  4. 给成果文件夹加版本日期，记录数据时段、数据类型和地图账户由谁维护。

B. 对方电脑有 Python：最省步骤的交付

海洋平台交付包/
  start_platform.py
  dist/
    index.html
    assets/         构建后的 Vue、Cesium 程序与样式
    data/           海洋 JSON 与海岸遮罩
    cesium/         Workers、Assets 等配套资源
    docs/           使用和交付说明
    licenses/       配套许可文件
    ...             保留构建生成的其他内容

保持 start_platform.py 和 dist 同级。对方运行 python start_platform.py，即可打开 http://127.0.0.1:8000/。无需 Node、前端编译工具、你的 CDS 账户或原始 NetCDF。已有服务占用 8000 时关闭旧服务，或运行 python start_platform.py --port 8001；地图令牌需允许实际端口。

C. 对方没有 Python

只把完整 dist 交给其静态网站维护者，通过现有 HTTP(S) 服务提供访问。访问者只需要支持 WebGL 的浏览器。当前没有额外提供一键桌面 exe，也没有把静态服务器打进 dist。

D. 你说的“独立网页”若严格指单个 .html

当前 Vue 构建不支持把全部程序、115 MB 数据、Cesium Workers 和运行资产变成一个可双击的完全离线 HTML。不能只复制 dist/index.html。常规独立交付用完整文件夹或一个网址；若必须单 HTML，需要另外设计导出版本，解决 Worker、资源寻址、数据内嵌和浏览器本地限制，不能拿旧版打包命令直接处理 Vue 入口。

E. 交付前哪些配置要改？

若继续由你维护地图账户，可以为该应用提供专用、限制范围的客户端令牌；接收者仅查看时无需改代码。若维护责任转给对方，由对方提供其地图令牌，你在构建前更换 .env.local 并重新 build。生产文件里的令牌已经编译进程序，只改外部 .env.local 不会改变已构建的网页。

不要把个人 CDS 配置、.venv、node_modules、.idea 或原始下载目录混进成果包。只看成果的人不需要这些内容。完整 dist 内的相对目录结构保持不变。

9. 给别人一个网址：开发者的发布流程

  1. 在维护电脑完成下载、处理、测试和构建。
  2. 让网站维护者把完整 dist 的内容放到站点的静态目录，例如网址根目录或 /ocean/ 子目录。
  3. 在地图账户配置实际网站访问地址，核对 HTTPS、域名、路径及端口；用另一台电脑打开发布网址。
  4. 验证 JS、CSS、Worker、海岸 JSON、海洋 JSON 都返回文件而非登录页或 404 页面，MIME 类型正确。
  5. 以后更新数据重新构建，成套替换发布版本。保留上个完整版本以便回退，避免更新过程中混用不同版本的 HTML、程序和数据。

vite.config.js 当前 base:'./'，适合保持目录结构的相对部署。子目录建议使用以斜线结尾的站点地址，例如 /ocean/；若服务器有固定前缀策略，也可显式配置 base 后重新构建。当前没有 Vue Router，不要求为每个不存在的资源都返回 index.html；资源不存在时返回真正 404 更利于排错。

服务器可为文本和 JSON 开启 gzip 或 Brotli，并避免长期缓存 index.html 和未带内容哈希的 data/*.json；assets 中带哈希的程序可长期缓存。数据较大，首访加载需实测；网页播放已有数据，不会自动在线下载 ECMWF 更新。

127.0.0.1 是访问者自己的电脑。把本机地址发给别人不会让其连接你的电脑。当前启动脚本只监听本机；公网发布应使用单位已有网站或静态托管服务，而不是直接将调试服务暴露到公网。

当前成果是静态展示；用户登录、私有数据、服务器下载队列、自动定时更新、数据分块接口均需要额外开发。完整离线还需要替换远程底图并验证许可及离线资源，不是仅断开网络测试数据色面即可。

10. 把 Vue 源码交给另一位开发者

提供 src、public/data、scripts、tests、根 index.html、package.json、pnpm-lock.yaml、pnpm-workspace.yaml、vite.config.js、.env.example、五个 Python 文件及说明。需要复现数据处理时另附原始 NetCDF 或获取步骤。不要直接复制你的虚拟环境；对方重建自己的 Node/Python 环境与账户配置。

pnpm-workspace.yaml 中有 Cesium 旧版本所需的 zip.js 2.7.34 兼容锁定与依赖构建策略，package.json 中也有 npm overrides；不要遗漏这些配置。升级 Vue / Vite / Cesium 时单独做修改，更新锁文件并测试；不要为换电脑顺手升级全部依赖。

GitHub 同时保存 Vue 与旧版时，应使用不同分支或清晰的不同目录。当前旧版分支已存在，Vue 版尚不能靠它恢复。需要托管 Vue 最新版时，应另提交完整 Vue 工程，排除个人 .env.local、CDS 配置和 node_modules；大数据文件继续按仓库约定处理。

11. 每次发布前的开发者验收表

  • 温度、盐度、海流、波高、波浪粒子均可显示；数据来源、单位、时段与实际元数据一致。
  • 小时与月平均切换正确；缺小时没有伪造补帧。拖动往返、松手定位、正倒放、循环、暂停、切速都可用。
  • 切换要素和快速拖动不闪空，失败时保留上一成功画面，图层和对象 URL 不持续增长。
  • 新文件导入不会被尚未结束的首次后台加载覆盖，分类导入不混配不同日期或不同网格。
  • 画质和不透明度生效；长来源文字不换出错位；点位框在数据信息上方，窄屏避让播放栏。
  • 测试与生产构建通过；至少打开一次 preview 或 start_platform，验证构建后而非只验证 dev。
  • 底图、配套 Worker 及 JSON 能加载；地图令牌允许实际访问地址。Bing 等外部底图短时失败可刷新重试，查看浏览器错误记录。
  • 接收者只拿交付文件夹也能启动；成果包没有 CDS 凭据，附有数据时段和版本记录。
